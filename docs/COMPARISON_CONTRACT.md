# Comparison contract v1

The design document contains the complete implemented field schema: [specification](superpowers/specs/2026-10-18-importproof.md). This user-facing contract resolves important interpretation points.

1. Inputs are caller-supplied byte sequences and filename format hints. SHA256 authenticates only the observed bytes. Filename does not establish source application. Header is row1; no automatic preamble skipping. CSV unquoted-empty is `blank`, quoted-empty `empty`; these are representation facts, not inferred NULL. Absent XLSX cells or ragged CSV padding are `missing` and need review.
2. Every supported table is compared by exact name by default. A single CSV/TSV can pair with a single XLSX sheet. Multiple XLSX sheets require names or an explicitly selected before_sheet/after_sheet pair. Excluded sheets are recorded assumptions. Added/lost sheets are observed differences.
3. Columns align by exact unique name or explicit one-to-one `column_map`; `#N` selects 1-based position. Duplicate/empty names retain order and trigger UNKNOWN even when positions can align. Explicit mapped renames are equivalent; unmapped missing/new names are observed column loss/addition, not automatic rename proof. Storage type changes in headers are differences too.
4. Keys are exact value+kind identities, including type. Duplicate and missing key groups are never paired arbitrarily. Numeric/date/whitespace rules do not normalize key identity. A missing key column retains column-loss evidence and an UNKNOWN alignment finding. Changed keys can appear as lost/added even if other cells look identical.
5. No key means positional alignment by default; each cell change is conditional on that assumption. With ignore_order, matches use exact or caller-declared semantic multiset signatures. Unmatched values are UNKNOWN identities, not invented edits. Multiplicity changes are retained; exact duplicate records remain a review issue. ignore_order also permits column order changes.
6. `text_columns` protects text storage; `numeric_columns` compares finite bounded Decimal text exactly, no epsilon/binary-float coercion. Different numeric spelling can be equivalent only when explicitly allowed. `date_columns` requires exactly one interpretation under stored date typing/declared strptime formats. Conflicting date interpretations are UNKNOWN. No locale/date-format guessing establishes equivalence.
7. Explicit trim/Unicode normalization/null tokens/ignored columns are transparent caller assumptions. Unknown keys and conflicting rule targets reject. Ignore rules do not resolve reader uncertainty such as unsupported workbook constructs. Ignored columns can contain unchecked values and formulas; no conclusion applies to them.
8. Raw/type/value violations produce CONFIRMED_LOSS observations; this label includes intentional changes. Suspected conversion mechanisms are separate findings. Whole-report UNKNOWN takes priority over confirmed observations but never hides their counts. Formula/error/unavailable-cell conclusions remain UNKNOWN; no calculation or macro/external reference executes. CSV formula-like strings also trigger review.
9. Report fields: schema_version, version, inputs with bytes/hash/reader metadata, policy, assumptions, findings, summary and truncated. Findings contain verdict/code/message/table and optional before/after evidence with original cell, column index, coordinate and source. CSV source line spans count CR/LF physical lines, not Unicode paragraph separators. XLSX coordinates refer to actual sheet/cell, raw numeric token in stored/raw, date display format retained.
10. `EQUIVALENT` excludes unsupported visual presentation. Numeric display-format change without numeric semantic permission is UNKNOWN; date-format change is a strict difference or declared date equivalence. Full fonts/fills/charts/printing/conditional-formatting/rendered display fidelity is not certified. Parsing limits/errors cannot establish equivalence. 2000-finding truncation forcesUNKNOWN; subsequent findings may be omitted, so category counts are lower bounds.

Reports do not infer whether a value was changed by Excel, LibreOffice, SQLite or a script. Controlled examples may document an externally known conversion setup, but that setup is not an inference made by ImportProof.

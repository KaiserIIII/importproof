# Reader behavior and boundaries

`read_document(bytes, filename, options=None)` returns JSON-compatible evidence and raises `ValueError` for invalid or unsafe inputs. CSV/TSV use the first physical record as headers; XLSX uses worksheet row 1. Every sheet is retained, including hidden sheets. Missing coordinates up to the last populated/explicit row and column become `missing` cells. An explicit cell without content is `blank`; an explicit empty string is `empty`. Header duplicates, blank headers, ragged CSV records, blank records, formulas, spreadsheet errors, and unsupported constructs produce issues. The comparison layer must treat unresolved reader issues as uncertainty.

CSV preserves original decoded record text and CR/LF physical line spans. `QUOTE_NOTNULL` in Python 3.13 distinguishes unquoted empty fields (`blank`, raw null) from quoted empty strings (`empty`, raw ""). Fields remain text: no automatic number/date/null inference. Automatic encodings are strict UTF-8, UTF-8 BOM, or UTF-16 BOM. Explicit supported encodings are utf-8, utf-8-sig, utf-16, cp1252, gb18030. CSV defaults to comma and TSV to tab. Consistent alternative or competing separators require explicit selection; the reader intentionally does not guess. `quotechar` is one character. Unknown input options reject.

XLSX is validated before openpyxl is invoked: ZIP paths, duplicate members, encryption flags, compression, expanded size, member count, macros/binary parts, external relationships/links, malformed XML, DTD/entity declarations, and duplicate relationship IDs are checked. Every XML/rels member is parsed with defusedxml forbidding DTDs, entities, and external references. Workbook loading uses `read_only=True`, `data_only=False`, `keep_links=False`. Formula text and its cached value are evidence only; formulas are never evaluated and external content is never fetched. Legacy XLS, XLSB, macro files, chartsheets, and unsupported workbook formats reject.

Numeric OOXML values come from the validated `<v>` text; both `raw` and `stored` preserve the numeric token exactly, including long integers, exponent notation, and decimal scale. No binary float enters numeric evidence. Date styles are identified using openpyxl's installed number-format tables. Serial-to-date conversion uses Decimal and microseconds, retaining original serial text in `stored`. Dates finer than microseconds, the fictitious Excel 1900 leap day, and duration formats produce issues. Date serials outside supported calendar range reject. ISO date cells retain their stored ISO text.

Each XLSX cell retains number format and style index. Document metadata retains a SHA-256 digest of the parsed stylesheet. This supports style provenance, but is not a renderer or complete visual comparison: fonts, colors, borders, conditional formatting, print appearance, rich text, merged-cell presentation, and other auxiliary constructs are not rendered. Rich text preserves base text, excludes phonetic guides from the value, and produces an issue. Names, hidden data, row attributes, unknown cell markup, and unsupported package parts produce issues rather than silent equality.

Fixed reader limits are 5 MiB compressed/input bytes; 50 MiB expanded XLSX; 1000 ZIP members; 20 worksheets; 50000 physical/worksheet rows including the header; 256 columns; 300000 rectangular materialized cells across all sheets; and 65536 characters per field, formula, cached value, or shared string. Sparse sheets are counted by the materialized rectangle, preventing tiny sparse inputs from producing huge documents. Worker time/result-size/process memory controls belong to the caller. XML trees are bounded by expanded size but can consume more RAM than compressed bytes; this is not a complete operating-system sandbox.

The reader tests use authored synthetic byte strings and hand-written OOXML ZIPs. They exercise actual parsing rather than mocking the libraries.
